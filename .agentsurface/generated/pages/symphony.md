# When agents become participants in product work.

Symphony explores how a product team changes when AI agents can research, critique, advise, and execute—and what humans must remain responsible for as that capability grows.

THE QUESTION

## What happens to the product-development lifecycle when the team includes agents?

Not “can an agent do the work?” The design question is where intent originates, where judgment happens, how context moves, who approves consequences, and how the team remembers what it learned.

WHY → PROBLEM → HYPOTHESIS

## The pivot made the real problem visible.

Symphony began with the promise of a multi-agent operating layer. Working through the idea exposed a more important challenge: coordination, authority, context, and verification matter more than the number of agents.

01 / ORIGIN
### Agent capability was the starting point.

Could a team of specialized agents make research, critique, planning, and execution feel like a coherent system?

02 / OBSERVATION
### Capability without boundaries creates ambiguity.

Advice can look like authorization. Context can disappear between conversations. Metered actions make “just try it” a consequential product choice.

03 / PIVOT
### Design the operating layer first.

The current experiment focuses on explicit handoffs, durable records, approval gates, and evidence-led expansion of authority.

CURRENT SYSTEM MODEL

## Human purpose. Agent leverage. Human responsibility.

This is a model of the current design direction—not a claim that every step is automated in the live product.

05

RESPONSIBILITY MAP

### The human does not disappear from the loop.

- Intent originates with the human.
- Advice can be delegated.
- Approval belongs to the exact action.
- Verification returns to the human and the record.

## What is real, what is designed, what is unknown.

The boundary is part of the case study. It prevents a compelling system diagram from becoming an unsupported product claim.

Implemented / documented

Designed / proposed

Still being explored

Each operating rule is a hypothesis about how people and agents can work together without confusing fluency for reliability.
