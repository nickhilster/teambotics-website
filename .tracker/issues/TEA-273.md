## Description

Repo-grounded follow-up from the 2026-05-08 `teambotics-website` sync.

Current repo state:

* `lib/chat/githubIngestion.ts` implements private GitHub knowledge ingestion.
* `scripts/ingest-github-knowledge.ts` supports manual ingestion.
* `/api/cron/ingest-github` is protected by `CRON_SECRET`.
* `vercel.json` schedules ingestion at `0 6 */2 * *`.

Needed outcome:

* Configure private repo ingestion safely in production.
* Trigger a protected manual run once.
* Confirm scheduled 48-hour refresh can run without exposing private repo URLs or sensitive files.

Required env:

* `CRON_SECRET`
* `GITHUB_INGEST_TOKEN`
* `GITHUB_INGEST_REPOS`
* `OPENAI_API_KEY`
* one Neon/Postgres URL

Acceptance criteria:

* Unauthenticated cron request is rejected.
* Authenticated manual cron or script run succeeds.
* Ingestion records source and run metadata.
* Selected files exclude env files, secrets, lockfiles, generated build output, and other low-signal sources.
* Chatbot can cite GitHub-derived knowledge only where appropriate.

## Comments

### Muse — 2026-11-13, verified live, then retired by owner decision

Verification found the ingestion configured and working, contrary to the tracker's stale Todo state: the 48-hour cron (`0 6 */2 * *` → `/api/cron/ingest-github`) had run successfully that same morning (2026-11-13T06:00Z) and the database held 550 GitHub-ingested documents (Code2Motion, StoryTeller, EasyBuddy, LTB Buddy repositories) alongside the public site corpus. It was also verified that the ingested content was not being served: the live configuration's allowed source types exclude `github`, and historic `chatbot_logs` matched sources only ever show the four public types.

As part of the TBW-002 migration to the unified NikBot backend, Nik decided on 2026-11-13: **disable the cron, keep the rows inert in the DB**. The cron entry was removed from `vercel.json` in the TBW-002 commit (`61c73cd0334d`, now on main and deployed); the ingestion route and code remain in the repo, and the 550 rows remain in the database, unreachable: the unified backend enforces a server-side allowlist of the four public source types judged by the `documents.source` column. This ticket is therefore canceled as superseded by the owner's decision — its verification work is recorded above. Re-enabling ingestion is a deliberate future decision: restore the cron entry in `vercel.json` and revisit the isolation invariants in NIK-003's contract doc first.
