## Description

**Origin:** Nik, 2026-11-09, after the TBW-006 / PR #41 review renders made it obvious side by side: "the product pages don't match the landing page in visual design. The product pages were not yet completed in the overhaul. Let's spec out that sprint/flash and add it to the tracker."

**Full spec:** `docs/product-pages-design-alignment-flash-2026-11-09.md` — this ticket is the tracker record; the spec carries the evidence table, phase gates and risks.

**Verdict:** the site currently runs two design systems. The 2026-10-10 overhaul shipped the landing page only, and the split is explicit in code — `styles/globals.css`: *"The consultancy homepage has its own editorial surface. Keep shared product pages unchanged."*

- **Landing (post-overhaul):** scoped `ConsultancyHome.module.css` — deep green `#193127` on warm cream `#fbfaf5`, flat ruled cards with square corners and no shadows, Geist Mono eyebrows, solid-ink rectangular CTAs, green footer/land strip and green Chat toggle (all via `.site-shell:has(.consultancy-home)` overrides).
- **Product pages (pre-overhaul):** the shared template `components/products/ProductCaseStudyContent.tsx` on the global system — page `#f7f8ff`, magenta accent `#b52d96`, layered hero gradients, glass pill tags/badges, pink-gradient pill buttons, 1.5rem-radius cards with coloured glow shadows, navy/magenta dark theme.

### Scope
- [ ] All 8 case-study slugs from the one template — ryfine, code2motion, ltb-buddy, redactorbuddy, mdownmanager, easybuddy, storytellr, recruiterbuddy — across en / fr-CA / es-419.
- [ ] Header, footer and Chat widget as they appear on product pages.
- [ ] **Content frozen:** no copy, translation, product-data, status-label or link changes. Presentation layer only.
- [ ] Out of scope, inventory only: legacy standalone routes not on the template (`/easybuddy`, `/MdownManager`, `/RedactorBuddy`, `/feedbackfish`, `/financebuddy`, `/poko`, `/symphony`, `/BOSS`) and the other pre-overhaul editorial pages (`/about`, `/everythings-computer`, legal).

### Decisions needed from Nik (Phase 0 gate — no build before these)
- [ ] **D1 Direction:** landing is the source of truth; product pages move to it.
- [ ] **D2 Dark theme:** single editorial surface (like landing), a dark variant re-derived from the green palette, or keep the current navy/magenta dark theme?
- [ ] **D3 Chrome:** full consultancy chrome on product pages (header, footer, Chat) vs body only. (Spec recommendation: full.)
- [ ] **D4 Buttons:** scope the landing button treatment to product pages vs change the global `.button--primary` estate-wide. (Spec recommendation: scoped first.)
- [ ] **D5 Product accents:** one uniform rule for per-product brand colours inside the aligned template — kept in a bounded slot, or dropped entirely.

### Flash phases
- [ ] **Phase 0 — Decisions + token mapping:** Nik answers D1–D5; mapping table (every product-page pattern → landing equivalent) approved; legacy-route inventory screenshotted for a follow-on decision.
- [ ] **Phase 1 — Token + chrome layer:** product-scoped tokens in the landing palette; header/footer/Chat treatment per D3; seam check on RyFine at 1280 + 390px.
- [ ] **Phase 2 — Hero:** rebuild the product hero on the landing grammar (flat surface, mono eyebrow/tags, heading weight, action row); includes the TBW-006 hero-clearance requirement (below).
- [ ] **Phase 3 — Body sections:** focus/detail cards, evidence list, stack chips → flat ruled treatment; no glow shadows or gradient tints left.
- [ ] **Phase 4 — Roll out + verify:** all 8 slugs × 3 locales verified by screenshot sweep (1280 + 390px; fr-CA/es-419 on at least two slugs; themes per D2); gates compared against a re-established `main` baseline; live deploy verified on two slugs.

### Relationship to TBW-006 / PR #41
- [ ] PR #41 is held open: the shrunken Chat pill still overlaps the `All products` hero button at 390/360 × 844 (en ~10px, fr-CA ~36px, es-419 ~35px). Phase 2 redesigns that hero — either TBW-006's clearance fix lands first and must not regress, or it folds into Phase 2 and closes here.
- [ ] TBW-006's 44px tap targets (header/footer) must survive the Phase 1 chrome work.

### Acceptance
- [ ] Landing → any product page reads as one visual system (palette, headings, buttons, cards, chrome) per the approved mapping table.
- [ ] Screenshot sweep complete per Phase 4; no content diffs (presentation layer only).
- [ ] TBW-006 mobile checklist passes on the new hero, or its blocker is explicitly closed inside this ticket.
