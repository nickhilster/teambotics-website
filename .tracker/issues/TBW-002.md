## Comments

### Muse — 2026-11-13, adapter shipped and live in production

The Teambotics assistant now runs on the unified NikBot backend (contract v1, NIK-003) through a thin adapter, merged to main as `61c73cd0334d` and verified live on teambotics.app the same morning, at Nik's direction to push NikBot into production for both sites today (the owner cutover approval for this ticket).

What changed: `app/api/chat/route.ts` now calls `runChatViaBackend` (`lib/chat/adapter.ts`) instead of the standalone `runChatRuntime`. Everything visitor-visible is preserved by construction: same route and response shape (including the `response` duplicate and `sessionId` semantics), same kill switch (the adapter checks this site's own live config first and returns the same offline response), same per-IP rate limit (same `takeRateLimitToken` and the same 429 body/headers), same moderation behaviour (the backend performs it for this profile with this runtime's exact refusal copy; 400s pass through untouched), and per-turn logging into this site's `chatbot_logs` with the same payload shape (verified live: user/assistant row pairs with correct modes after the preview probes). The lead form (`/api/leads`) is untouched. The standalone runtime remains in the repo, unused by the route.

Validation: unit tests 39/39 across 14 files (including 6 new adapter tests: offline short-circuit, 429, header/mapping shape, moderation pass-through, backend-failure fallback, missing-env fallback); typecheck clean; `next build` clean. Preview validation ran on branch preview deployments rather than testing.teambotics.app — that hostname is still bound to the stale `codex/website-overhaul-spec` branch, so it cannot validate current code; the substitution is recorded here deliberately. On the adapter preview, all 8 `PUBLIC_CHAT_EVALUATORS` pass with their expected sources; cross-site leakage probes are clean in both directions (GitHub-ingested roadmap bait returns a grounded refusal with zero sources; Nik-resume questions refuse; the private-client boundary answers with the disclosure boundary, naming nobody). One preview incident, resolved as environmental: the first probes against a freshly redeployed preview deployment hung past 150s while the platform warmed; the same deployment then answered in ~3s and stayed healthy — no code change resulted.

Two companion changes landed under the same direction: the site corpus was stale and has been reseeded (TEA-272: 13 changed + 16 missing documents embedded, verified 41/41 current — before this, RyFine, RedactorBuddy, MDownManager and RecruiterBuddy had no documents in the database at all), and the private GitHub ingestion cron was disabled at Nik's decision (TEA-273: rows kept inert; the unified backend's server-side allowlist makes them unreachable regardless). Cost note: the migration removes this site's per-request OpenAI retrieval/generation duplication — one backend serves both sites; the adapter adds one server-to-server hop. Rollback: point `app/api/chat/route.ts` back at `runChatRuntime` (one import + one call) and redeploy; restoring ingestion is re-adding the cron entry in `vercel.json`.
