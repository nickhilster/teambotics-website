WCAG 2.1 AA: Conditional Pass — Remediation Required The main Teambotics site (/, /about, /privacy, /terms, /products/*) passes axe automated checks on most pages with no critical barriers to task completion. However, three serious issues require immediate attention: a scrollable table lacking keyboard access on /privacy, confirmed color-contrast failures on the /easybuddy standalone page, and missing aria-invalid/aria-describedby on invalid form fields site-wide. Several moderate issues around landmark structure, mobile drawer ARIA, and heading semantics also need addressing before the site can claim full WCAG 2.1 AA conformance.

Top 5 Priorities

  • 1
    /privacy — Scrollable table not keyboard accessible Serious

    WCAG 2.1.1 (A). A data table on the Privacy Policy page is not reachable via keyboard. Add tabindex="0" to the scrollable container so keyboard users can scroll it.

  • 2
    /easybuddy — 18 color-contrast violations Serious

    WCAG 1.4.3 (AA). Inline styles use rgba(255,255,255,0.4) and rgba(255,255,255,0.45) at small font sizes producing ratios of 3.47–4.47:1 against dark backgrounds, all below the 4.5:1 threshold.

  • 3
    All pages — No skip-to-content link Serious

    WCAG 2.4.1 (A). There is no skip navigation link. Keyboard and screen-reader users must tab through the full header (logo + language switcher + theme toggle + 5 nav links) on every page load.

  • 4
    Contact form — Missing aria-invalid + aria-describedby on error state Moderate

    WCAG 1.3.1 (A) / 3.3.1 (A). When the form is submitted with invalid data, visual error messages appear but fields do not receive aria-invalid="true" or aria-describedby pointing to the error, so screen readers cannot programmatically associate the error with its field.

  • 5
    /about — Duplicate main landmark Moderate

    WCAG 1.3.6 / Best practice. The about page renders two <main> elements. The shell renders one and the page component renders another inside it, triggering three axe landmark violations. Screen reader virtual cursors and landmark navigation become ambiguous.

3. Accessibility Findings

Methodology note: axe-core 4.9.1 was injected via CDN and run with wcag2a, wcag2aa, wcag21a, wcag21aa, best-practice rules on every page. DOM inspection and manual checks supplement automated results. The color-contrast rule was marked "incomplete" by axe on most Teambotics-brand pages (not /easybuddy) because background images/gradients prevented automated measurement — those were manually spot-checked and passed.
Site-wide (all pages)
No skip-to-content link
Serious
PagesAll pages ViewportsDesktop + Mobile WCAG2.4.1 Bypass Blocks (Level A) axe rulebypass (not triggered — element absent)

No <a href="#main-content">Skip to main content</a> (or equivalent) exists anywhere in the DOM. Keyboard users must tab through the full header on every page: logo link + language selector + theme toggle + 5 navigation links = 8 tab stops before reaching page content. On mobile with the hamburger, it's slightly fewer, but the problem persists.

Recommended Fix Add a visually-hidden but focusable skip link as the very first child of <body>:
<a href="#main-content" class="skip-link">Skip to main content</a>
Add id="main-content" to the <main> element. Style the skip link to appear only on focus.
Contact form: fields not associated with error messages programmatically
Moderate
Pages/ (home contact section) ViewportsDesktop + Mobile WCAG1.3.1 Info and Relationships (A), 3.3.1 Error Identification (A) Selector#lead-name, #lead-email, #lead-message

On invalid form submission, three <span role="alert"> error messages render visually but: (1) the associated inputs do not receive aria-invalid="true", (2) there is no aria-describedby linking each input to its error <span>. Screen readers announce the alerts via live region, but cannot determine which field is invalid from the input's own accessible context. Additionally, focus is not programmatically moved to the first invalid field.

<!-- Current (problematic) --> <input id="lead-name" type="text" required> <span role="alert" class="lead-form__error">Please add your name.</span> <!-- Required --> <input id="lead-name" aria-invalid="true" aria-describedby="lead-name-error" ...> <span id="lead-name-error" role="alert" class="lead-form__error">Please add your name.</span>
Recommended Fix On validation failure: set aria-invalid="true" on each failing field; set aria-describedby pointing to its error span (add a matching id to each error <span>); move focus to the first invalid field or the status summary.
Theme toggle button: no announced state
Minor
PagesAll (header) WCAG4.1.2 Name, Role, Value (A) Selectorbutton[aria-label="Toggle color theme"]

The theme toggle button has a static label "Toggle color theme" but no aria-pressed attribute to indicate current state (light or dark). Screen reader users cannot determine the active theme without additional context.

Recommended Fix Add aria-pressed="true/false" that reflects current dark/light state, or dynamically update the aria-label to "Switch to light theme" / "Switch to dark theme".
LinkedIn footer link: no "opens in new tab" indication
Minor
PagesAll (footer) WCAGWCAG 2.4.4 Link Purpose (AA) — best practice Selectorfooter a[href*="linkedin"]

The LinkedIn link opens in a new tab (target="_blank") but has no visual indicator or accessible announcement of this behaviour. The rel="noopener noreferrer" is correctly set (good). However, screen reader users should be informed via aria-label or a visually-hidden span.

Recommended Fix Change to: <a href="..." target="_blank" aria-label="LinkedIn (opens in new tab)">LinkedIn</a>
Language switcher option labels missing diacritics
Minor
PagesAll (header) WCAGBest practice / pronunciation Selectorselect[aria-label="Language"] option

Option values are "Francais" and "Espanol" — missing accent marks. Screen readers will mispronounce these as English words rather than French/Spanish. Should be "Français" and "Español".

Recommended Fix Update option text: <option value="fr-CA">Français</option> and <option value="es-419">Español</option>.
CTA section H2 accessible name polluted by decorative chip text
Moderate
Pages/ (home — CTA thesis section) WCAG1.3.1 Info and Relationships (A) Selectorh2.cta-section__title > span.cta-thesis

The fifth H2 on the home page contains <span> decorative chips ("Product", "Discovery") inside the heading. Screen readers read the heading as "ProductDiscoveryQuality output begins with a quality input process." — the decorative tag words prepended to the headline create a confusing heading outline and accessible name. Document outline tools will show this garbled heading.

<h2 class="cta-section__title"> <span class="cta-thesis"> <span class="cta-thesis__meta"> <span class="cta-thesis__chip">Product</span> <!-- decorative --> <span class="cta-thesis__chip">Discovery</span> <!-- decorative --> </span> <span class="cta-thesis__headline">Quality output begins with a quality input process.</span> </span> </h2>
Recommended Fix Add aria-hidden="true" to the .cta-thesis__meta span so chips are excluded from the heading's accessible name: <span class="cta-thesis__meta" aria-hidden="true">
Mobile Navigation (375×812)
Mobile drawer: missing ARIA pattern (no aria-expanded, no role, no focus trap)
Moderate
PagesAll (mobile viewport) ViewportsMobile WCAG4.1.2 Name, Role, Value (A); 2.1.2 No Keyboard Trap (A) Selectorbutton[aria-label="Open navigation"], .mobile-drawer

Three related issues were observed on the mobile hamburger drawer: (1) The trigger button retains the label "Open navigation" even when the drawer is open — it should switch to "Close navigation" or use aria-expanded. (2) aria-expanded is absent from the button entirely, so screen readers cannot determine open/closed state. (3) The drawer element (.mobile-drawer) has no role="dialog" or aria-modal="true" and does not trap focus — a keyboard user could tab outside the drawer while it is visually open.

Recommended Fix (1) Add aria-expanded="false" to the trigger, toggling to "true" when open. (2) Update aria-label or add aria-controls="mobile-drawer" already present but complement with expanded state. (3) On open: add role="dialog" + aria-modal="true" + aria-label="Navigation menu" to .mobile-drawer; trap focus inside using a focus-trap utility; move focus to first link on open; restore focus to trigger on close.
/about
Duplicate <main> landmark — nested main elements
Moderate
Pages/about WCAG1.3.6 Identify Purpose (AAA) / ARIA best practice axe ruleslandmark-main-is-top-level, landmark-no-duplicate-main, landmark-unique Selector.site-shell > main (outer), .about-page (inner)

Three axe violations triggered by the same root cause: .about-page renders a second <main> element nested inside the shell's <main>. ARIA spec mandates exactly one main landmark per page. Screen readers using landmark navigation (e.g. NVDA+Q or VoiceOver rotor) will encounter two "main" regions, causing confusion about primary content boundaries.

Recommended Fix Change the .about-page component's root element from <main> to a semantically neutral element such as <div> or <article>. The shell already provides the single <main> wrapper.
/privacy
Scrollable table not keyboard accessible
Serious
Pages/privacy WCAG2.1.1 Keyboard (A) axe rulescrollable-region-focusable Selectortable (wrapping DIV)

The Privacy Policy page contains a data table whose content overflows horizontally. The table's parent container is scrollable but has no tabindex="0", meaning keyboard users cannot scroll or access content that is off-screen. Mouse-only users can scroll, but keyboard-only and switch-access users cannot reach clipped table content.

Recommended Fix Wrap the table in a <div role="region" aria-label="Data table" tabindex="0" style="overflow-x:auto">, or add tabindex="0" directly to the scrollable wrapper div. Alternatively, redesign the table to be responsive and avoid overflow at small viewports.
/easybuddy (standalone page)
18 elements fail color-contrast (inline styles using rgba opacity)
Serious
Pages/easybuddy WCAG1.4.3 Contrast Minimum (AA) — 4.5:1 for normal text axe rulecolor-contrast (18 nodes) SelectorMultiple (see details)

Multiple inline styles use rgba(255,255,255,0.4) (computed #666, ratio 3.65:1) and rgba(255,255,255,0.45) (computed #777, ratios 4.46–4.47:1) against very dark backgrounds. All three groups fail the 4.5:1 threshold for normal-weight text at 8–12px.

/* Failing instances (sample) */ span { color: rgba(255,255,255,0.4); } /* ratio 3.65:1 vs #000 — FAIL */ p { color: rgba(255,255,255,0.45); } /* ratio 4.46:1 vs #061722 — FAIL */ div { color: rgba(255,255,255,0.45); } /* ratio 4.47:1 vs #080808 — FAIL */
Recommended Fix Replace opacity-based white with absolute color values. Use at minimum rgba(255,255,255,0.55) (~5.5:1 on #000) or switch to #8a8a9a palette tokens. For the "by TeamBotics" attribution text, use rgba(255,255,255,0.6) or increase font size to 18.67px+ (large text threshold, allowing 3:1).
Heading order skipped (H1 → H4) in 5 locations
Moderate
Pages/easybuddy WCAG1.3.1 Info and Relationships (A) — WCAG best practice axe ruleheading-order (5 nodes)

The page jumps from H1 directly to H4 in feature card sections (e.g., "Customer Service Simulation", "Real-Time Diagnostics", "Reduces Turnover & Stress", etc.). Screen readers and document outline tools rely on sequential heading hierarchy for efficient navigation. Skipping levels disrupts navigation and page structure understanding.

Recommended Fix Change H4 elements in feature grids to H2 or H3 as appropriate to the document hierarchy, or introduce intermediate H2/H3 section headings above the feature grids to maintain sequential levels.
Missing main landmark + 15 regions outside landmarks
Moderate
Pages/easybuddy WCAG1.3.6 / ARIA landmark best practice axe ruleslandmark-one-main, region

The standalone EasyBuddy page has no <main> landmark. All 15 content <section> elements fall outside any landmark. Screen reader users who navigate by landmarks (NVDA forms mode, VoiceOver rotor) will find no navigable structure — all content appears as one undifferentiated block.

Recommended Fix Wrap the page's content sections in a <main id="main-content"> element. Give each major <section> an aria-label or aria-labelledby pointing to its visible heading.
Scrollable table inside /easybuddy not focusable (tabIndex=-1)
Moderate
Pages/easybuddy WCAG2.1.1 Keyboard (A) Selectortable (tabIndex=-1)

Same pattern as /privacy: a table element has tabIndex=-1 (programmatically set, not keyboard-reachable). Any overflowing content within it cannot be accessed via keyboard.

Recommended Fix Change table's tabindex from -1 to 0, or wrap in <div tabindex="0" role="region" aria-label="Comparison table" style="overflow-x:auto">.
/nonexistent (404)
404 page: <title> does not identify error state
Minor
Pages/nonexistent (404) WCAG2.4.2 Page Titled (A) Observed title"Teambotics" (expected: "404 — Page Not Found | Teambotics")

The 404 page's <title> element is "Teambotics" — identical to the home page. Screen reader users who land on this page and check the title for context will not know they reached a not-found error. Browser history and tab labels are also unhelpfully generic.

Recommended Fix Update the 404 page metadata: <title>404 — Page Not Found | Teambotics</title>.

5. Remediation Checklist Prioritized

Ordered by severity then effort. Effort: S = <1hr, M = half-day, L = multi-day

#1
Add skip-to-content link SeriousS
Insert <a href="#main-content" class="skip-link">Skip to main content</a> as first child of <body>. Add id="main-content" to <main>. CSS: visually hidden until :focus-visible.
#2
Fix scrollable tables on /privacy and /easybuddy SeriousS
Add tabindex="0" to the scrollable wrapper div on both pages, or use role="region" aria-label="...". Two separate files to update.
#3
Fix color-contrast failures on /easybuddy SeriousM
Replace all inline rgba(255,255,255,0.4) and rgba(255,255,255,0.45) with values achieving ≥4.5:1. Minimum safe value: rgba(255,255,255,0.55) on pure-black backgrounds, or use absolute hex values from the Teambotics design token palette.
#4
Add aria-invalid + aria-describedby to contact form error state ModerateS
On validation failure: set aria-invalid="true" on each failing field, assign unique IDs to each error <span>, add aria-describedby to each field pointing to its error span. Move focus to first invalid field or the status message.
#5
Fix duplicate <main> on /about ModerateS
Change the root element of the AboutPage component from <main> to <div> or <article>. The shell already provides the <main>.
#6
Fix mobile drawer ARIA pattern ModerateM
Add aria-expanded to hamburger toggle button (dynamic). Add role="dialog", aria-modal="true", aria-label="Navigation menu" to .mobile-drawer. Implement focus trap on open; restore focus on close. Update button label to toggle between "Open navigation" / "Close navigation".
#7
Fix footer link contrast in dark theme ModerateS
Footer link color in dark mode is rgb(89,97,136) → 3.26:1 against the dark background. Increase to at least rgb(120,130,175) (~4.5:1). Update the --color-text-secondary token for footer context or add a dedicated .site-footer a { color: ... } override.
#8
Fix accent pink contrast in light theme for normal-weight small text ModerateS
Accent pink (rgb(207,58,169)) on the light background (rgb(247,248,255)) is 4.10:1 — fails for normal text. For eyebrow/kicker text at 10px, this is a clear failure. Darken the light-theme accent to ~rgb(175,35,140) which achieves ≥4.5:1, or apply only to elements meeting large-text criteria.
#9
Add aria-hidden to decorative CTA chips inside H2 ModerateS
Add aria-hidden="true" to .cta-thesis__meta to prevent "Product" and "Discovery" from polluting the H2 accessible name. Verify heading outline reads only the actual headline text.
#10
Fix heading hierarchy on /easybuddy (H1 → H4 skips) ModerateM
Audit the full /easybuddy heading structure. Replace H4 elements in feature card grids with H2 or H3. Introduce labelled section headings at H2 level if needed to maintain logical hierarchy across 5 affected locations.
#11
Add main landmark + label sections on /easybuddy ModerateM
Wrap all content sections in a <main id="main-content">. Add aria-labelledby to each <section> pointing to its heading, so landmark navigation works correctly.
#12
Update theme toggle to expose current state MinorS
Add aria-pressed="true/false" to the theme toggle button reflecting current dark/light state, so screen reader users know the current theme without visual inspection.
#13
Fix 404 page title MinorS
Update the 404 page's Next.js metadata export to use title: "404 — Page Not Found | Teambotics".
#14
Announce external link for LinkedIn MinorS
Add aria-label="LinkedIn (opens in new tab)" to the LinkedIn footer anchor.
#15
Fix language option labels — add diacritics MinorS
Change "Francais" → "Français" and "Espanol" → "Español" in the language switcher option elements for correct screen-reader pronunciation.
